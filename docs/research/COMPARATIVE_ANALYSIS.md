# Comparative Analysis: Steam Emulator Wrappers & Mesh VPN Orchestration

> Status: initial architecture audit (Phase 1). Evidence paths reference the
> reference corpus cloned into `.research/` (gitignored — never committed).

## 1. Goldberg-family forks vs. ReFix

### 1.1 `steam_api` handling: replacement vs. proxy-forwarding

| | **gbe_fork** (Detanup01) | **gse_fork** (alex47exe) | **ReFix** (Coronitaa) |
| --- | --- | --- | --- |
| Model | Full drop-in **replacement** of `steam_api(64).dll` / `libsteam_api.so` | Same (direct fork of gbe_fork) | **Proxy chain**: original renamed to `steam_api64_valve.dll`, proxy forwards 1055+ exports via ASM jump table (`src/steam_fwd.asm`); plus `winmm.dll` loader proxy and EOS proxy |
| Backup convention | none needed (replaces) | same | `.orig` / `_o.dll` / `_valve.dll` suffixes; uninstaller restores |
| Extra loaders | `steamclient` loader path (`tools/steamclient_loader`) for ColdClient-style launch without touching game DLLs | inherited | `winmm.dll` proxy forces early load |

**Implication for drop-gse:** gbe_fork/gse_fook's replacement model is simpler
to automate and works on Linux natively; ReFix's forwarding model preserves the
real Valve DLL but is Windows/MSVC-only. The engine targets **gbe_fork/gse_fork
as primary**, with a documented non-goal of shipping ReFix (license + platform,
§1.5).

### 1.2 Steam networking interfaces

- **gbe_fork**: one translation unit per interface under `dll/dll/`
  (`steam_networking.h`, `steam_networking_messages.h`,
  `steam_networking_sockets.h`, `steam_matchmaking.h`, `steam_user.h`,
  `steam_gameserver.h`, …), plus a real `ISteamNetworkingSockets` backend in
  `networking_sockets_lib/`. Versioned SDK shims in `sdk/steam/`.
- **gse_fork**: identical surface (fork); adds `known_ips[16]` per peer,
  cross-app messaging flag, graceful `exit_on_unknown_interface` behavior.
- **ReFix**: full emulation only for Unreal titles (`src/unreal_steam_emu.cpp`);
  otherwise hooks matchmaking/lobby calls on top of the forwarded Valve DLL.

### 1.3 LAN broadcast & lobby discovery

All three converge on the same wire behavior:

- **UDP port 47584** (`DEFAULT_PORT`, `dll/network.h`; also
  `ReFix.ini [Network] ListenPort=47584`).
- Broadcast targets: computed subnet broadcast addresses +
  `255.255.255.255` every ~60 s (`network.cpp::get_broadcast_info()`),
  **plus custom targets from `custom_broadcasts.txt`**
  (parsed into `settings.custom_broadcasts`).
- Packet format: protobuf `Common_Message` (`dll/net.proto`),
  announce handled by `handle_announce()`.
- Lobby discovery via `ISteamMatchmaking` request/response over the same
  channel; Source query ports additionally exposed (`source_query.cpp`,
  `NUM_QUERY_PORTS=10`).

**Key seam:** `custom_broadcasts.txt` is the sanctioned mechanism to redirect
LAN discovery onto a mesh VPN — no global packet capture required. This is the
core integration point of drop-gse.

### 1.4 Configuration layouts

Runtime config read from `<game_dir>/steam_settings/` (both forks;
`settings_parser.cpp`):

```
configs.main.ini        # identity, ports, save paths (user::saves::local_save_path)
configs.app.ini         # DLC, depots, branches
configs.user.ini        # per-user overrides
configs.overlay.ini     # overlay toggles
steam_appid.txt         # app id
steam_interfaces.txt    # generated by tools/generate_interfaces
custom_broadcasts.txt   # ← mesh peer list goes here
stats.json / items.json / branches.json / mods.json / ...
```

ReFix instead uses a single `ReFix.ini`
(`[Game] EngineType`, `[Online] Mode=goldberg|valve`, `[Steam] MaskAppId`,
`[Network] CustomBroadcasts`, `[Unreal.Networking] DiscoveryPort=47584`).

## 2. Auto-patching & generation pipelines

| Tool | Language | AppID detection | Binary patching | Config generation | Take |
| --- | --- | --- | --- | --- | --- |
| **SteamRoll** (nordicnode) | C#/.NET 8 | registry + `libraryfolders.vdf` | in-place, backup `.original`, hash-idempotent (`GoldbergPatcher.cs`) | `steam_settings/`, `steam_appid.txt`, `steam_interfaces.txt` (regex scan of DLL exports, `GoldbergScanner.cs`) | best reference pipeline incl. PE-import DRM/anti-cheat heuristics (`DrmDetector.cs`) |
| **goldberg-patcher** (eligamii) | Rust | none | recursive replace, `non_gbe_patched_*.backup` | none | minimal; proves the Rust replacement loop is tiny |
| **GSE-Generator** (brunolee-GIT) | batch/PS | Google→steamdb scrape | swap keeping `<name>_o.dll`; validates DLL bitness via 7z listing | rich sidecar: DLC, languages, achievements + images | brittle scraping; achievement schema fetch pattern useful |
| **gse_fork_tools** (alex47exe) | Python | `-find` web search or SteamKit login | none | authoritative `steam_settings` generation from official Web API (achievements schema, UGC, item defs, branches.json) | best config-generation reference; login-based data beats scraping |
| **SteamEmuUtility** (turusudiro) | C# (Playnite plugin) | Playnite library / ACF parse | **none — ColdClientLoader launch** | `ColdClientLoader.ini`, achievements, languages, controller configs | zero-touch alternative: wrap launch rather than patch files |

**Engine decision:** gse-engine adopts SteamRoll's patch loop shape
(scan interfaces → backup → replace → write sidecar configs, all
hash-verified/idempotent) in Rust, with config generation patterns from
gse_fork_tools, and evaluates the ColdClientLoader approach as a fallback for
games where file patching fails.

## 3. Mesh VPN orchestration

### Tailscale

- Ephemeral nodes via **ephemeral auth keys**
  (`tailscale up --auth-key=…`) or `tailscaled --state=mem:`; auto-removed
  30–60 min after last activity, immediately on `tailscale logout`
  ([ephemeral nodes KB](https://tailscale.com/kb/1111/ephemeral-nodes)).
- Coordination plane is Tailscale-hosted (Coordination server) — no
  self-hostable control plane without Headscale.
- **Drop already embeds a tailscale client crate** (C ABI bindings around the
  Go library) at `desktop/src-tauri/tailscale/` — provisioning can happen
  in-process without CLI dependency.

### ZeroTier

- Self-hosted controller option: the service API exposes controller routes
  (`POST /controller/network`, member authorization) on `localhost:9993`,
  token from `authtoken.secret`, header `X-ZT1-AUTH`
  ([zerotier-one-api-spec](https://github.com/zerotier/zerotier-one-api-spec)).
- Client join/leave: `POST/DELETE /network/{id}` on the local service API.
- L2 semantics: networks carry a `broadcastEnabled` flag and controller-side
  `enableBroadcast`/`multicastLimit` — native UDP broadcast works across the
  virtual network, so emulator LAN discovery functions without redirection
  once peers share a network.

### Provisioning strategy (per-room ephemeral meshes)

1. Host creates a room → server provisions a fresh ephemeral credential set:
   - Tailscale: one reusable **ephemeral auth key** scoped to an ACL tag/app
     policy for this room.
   - ZeroTier: new network ID on a controller (self-hosted or Central API)
     with `enableBroadcast=true`, members authorized on join.
2. Server distributes credentials to approved room members over Drop's
   authenticated client API (WebSocket notifications channel).
3. Clients join the mesh, write peer addresses into
   `custom_broadcasts.txt`, launch.
4. On teardown: restore binaries, remove configs, `tailscale logout` /
   leave network; ephemeral state evaporates.

### Binding emulator traffic through the mesh

No OS-level capture needed: Goldberg sends unicast/broadcast probes to the
addresses listed in `custom_broadcasts.txt` over port 47584. Pointing that
file at room peers' mesh IPs (and enabling broadcast on ZeroTier nets)
delivers lobby discovery across the tunnel. In-game session traffic then flows
over the emulated Steam networking sockets, which use ordinary UDP between
discovered peers — routed by the mesh interface by virtue of the peer
addresses being mesh-scoped.
